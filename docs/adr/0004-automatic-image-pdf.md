# ADR 0004：图片重命名后自动按题名生成 PDF

日期：2026-09-08。状态：本次实现采用。

## 用户需求与边界

图片按 Excel 页次改名后，自动将同一文件图片合成以文件题名命名的 PDF；例如
“验收文件 / 6-10”生成五页 `验收文件.pdf`。用户明确要求自动生成、不另开页面，
后续要求控制测试、检验与审查数量。

实现沿用四个标签页和现有页次推导，单文件夹与批量图片任务都自动生成。
本次默认 PDF 存在图片目录，保留 JPG；相同题名跨行归并、页码升序排列。
同名 PDF 重跑更新，题名改变后遗留的旧 PDF 不自动删除。不同题名在 Windows
大小写不敏感规则下发生重名时，在首次改名前提示冲突，避免覆盖不同题名成果。

## 路线比较

| 路线 | 可行性与代价 | 决定 |
| --- | --- | --- |
| ReportLab + Pillow | 成熟 PDF 库；直接嵌入 JPG，Pillow 读取尺寸、方向及验证内容 | 采用 |
| img2pdf | 无损合并成熟，但常规依赖含 pikepdf/qpdf，增大旧系统二进制打包面 | 未采用 |
| Pillow 直接保存 PDF | 代码较短，但容易走图像重新编码路径 | 未采用 |
| 手写 PDF/JPEG 解析器 | 依赖少，但格式、色彩、方向实现与维护成本更高 | 未采用 |

固定运行依赖 `reportlab==3.6.13`、`Pillow==9.5.0`，保持 Python 3.8.10、
Tkinter 和 PyInstaller 4.10 onedir。独立 PDF 解析器 `pypdf==4.3.1` 及其
`typing_extensions==4.13.2` 仅用于构建侧测试，不是应用运行依赖。

ReportLab 3.6.13 官方元数据要求 Python >=3.7,<4、Pillow >=9.0.0；选定两包均
有 cp38 Windows x64 wheel。9.5.0 是保守固定选择，并非对后续版本 Win7 支持
情况作结论；真实 Win7 SP1 x64 兼容性仍待目标机实测。

来源：[ReportLab 元数据](https://pypi.org/pypi/reportlab/3.6.13/json)、
[Pillow 元数据](https://pypi.org/pypi/Pillow/9.5.0/json)、
[img2pdf 依赖元数据](https://pypi.org/pypi/img2pdf/0.6.3/json)。

## 实现与失败边界

- 应用服务使用本次 Excel 解析形成的图片计划组织 PDF，不读取历史执行记录。
- `infrastructure/pdf_writer.py` 验证真实 JPEG 并输出 PDF，UI 只显示统计。
- ReportLab 直接读取 JPEG 路径，使用 DCTDecode 原数据流；不重新压缩 JPG。
- 每张图片一页，按尺寸/DPI 建页，缺省 72 DPI；EXIF 旋转/镜像采用画布变换，
  不强制 A4，不增加封面、页码、OCR、PDF/A 或完整 ICC 色彩管理功能。
- 单目录或整批在首次改名前验证图片和 PDF 目标目录冲突。
- 单个 PDF 写入同目录临时文件，完整生成后替换目标。失败清理临时 PDF 并保留
  原有同名 PDF；已完成的 JPG 改名及其他 PDF 不回滚，也不复制备份。
- 错误携带失败对象、原因与已完成图片/PDF 数量，批量遇错停止后续目录。

## 验证策略

只进行必要回归一轮、既有双便携目录与发布 ZIP 自检一轮，不增加多轮独立审查。
PDF 测试覆盖代表性的五页合并、页序/原始 JPEG 字节、重跑、方向与失败边界；
冻结 `--smoke-test` 实际生成两张 JPEG 和一份 PDF，以覆盖新增依赖收集。
当前机通过情况由本次执行记录报告，Win7 实测不由开发机结果替代。
