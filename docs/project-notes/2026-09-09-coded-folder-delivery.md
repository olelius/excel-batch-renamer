# v0.3.1 编码来源文件夹兼容

## 需求纠正与实现

用户明确待改名对象是 `I74-6-256——` 文件夹，前文目标为 `256——验收文件`。
不是把完整编码作为工作表名称：文件夹任务表仍按数字序号 256 查找名称；
图片工作表仍用数字 `256`，图片任务和文件夹任务保持分离。

在既有 `extract_folder_sequence` 中增加编码来源分支，取 `——` 前末段数字；
旧三位前缀优先识别，创建/重命名目标仍输出三位数字。没有新依赖或 UI 页面。
来源编码接受半角 `-` 连接的字母数字段，末段为正整数；空名称行保留现状。
不同源目录归一到同号时继续拦截，避免猜测应该改哪一个。

共享解析器使改名前后的目录都能绑定数字图片工作表；JPG 页码与 PDF 逻辑不变。
文件夹任务序号仍从 1 连续到 n，本次未扩展成任意稀疏序号导入。
