# v0.4.1 PDF 起始页命名

## 修复内容

自动生成的 PDF 从 `文件题名.pdf` 调整为 `三位起始页+文件题名.pdf`，中间不加
分隔符。起始页复用已经用于图片命名的页次，不新增数据来源：

- `文件题名=验收文件`、`页次=6-10` 输出 `006验收文件.pdf`；
- 最后一项 `页次=023-045` 仅使用起始页，输出 `023验收文件.pdf`；
- 结束页 045 不写入 PDF 名称；PDF 内容仍包含 023 至 045，共 23 页；
- 同题名跨行归并时使用该组最小页码作为起始页；
- 起始页或题名变化后遗留的旧 PDF 仍按既有规则保留，不自动清理。

单文件夹、旧批量图片服务和 v0.4.0 双目录编排均复用同一实现，因此行为一致。

## 验证与打包

按用户要求不扩展测试矩阵，将已有五页验收用例替换为 `023-045` 代表场景，并同步
原有断言。一次完整回归 96 项通过，0.837 秒；`compileall`、`pip check`、
`git diff --check` 通过。

双 onedir 构建及便携运行、发布 ZIP 解压自检通过；测试版和正式版均为 994 个文件，
分别为 29,719,881 与 29,721,407 字节。日志位于：

- `.artifacts/verify-pdf-prefix-v0.4.1.log`
- `.artifacts/build-pdf-prefix-v0.4.1.log`
