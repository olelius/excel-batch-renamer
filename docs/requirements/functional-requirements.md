# 功能需求

状态：已确认

## 已确认范围

系统提供三个相互独立的任务模式：

1. 文件夹创建任务；
2. 文件夹重命名任务；
3. 图片重命名任务。

每个任务模式必须单独选择自己的任务目录，不共享全局目录。

本系统定位为受控流水线中的小型作业插件。输入由上游人工流程保证符合规范，不扩展为通用文件清洗、修复或数据治理工具。

## 任务表

- 文件格式固定为 `.xlsx`。
- 客户机可能安装 WPS、Microsoft Excel 或其他办公软件，也可能不存在可调用的 Excel 组件。
- 程序必须独立读取 `.xlsx`，不得调用 Microsoft Excel/WPS、COM、宏或 Office 插件。
- 文件夹创建和文件夹重命名模板的表头固定在第一行，数据从第二行开始。
- 图片重命名任务表的表头固定在第三行，数据从第四行开始；程序忽略图片工作表的第一行和第二行内容。
- 匹配表头前删除其中的全部空白字符，包括普通空格、全角空格和制表符；该规则只作用于表头，不删除数据单元格内容中的空格。
- 程序不得扫描或推测其他表头行。
- 有效数据行必须连续排列，不存在空白行之后还有有效数据。
- 从第二行开始读取，遇到首个完全空白数据行即结束。
- 文件夹创建与文件夹重命名使用固定列：
  - `序号`
  - `文件夹名称`
- `序号` 从 1 开始连续排列到 n。
- `序号` 按三位数字格式化，不足三位时在左侧补零。
- 业务保证不会出现需要四位表示的序号，程序不增加上限校验或四位编号处理分支。
- 文件夹创建任务允许 `文件夹名称` 单元格为空。
- 文件夹创建与文件夹重命名模板只有一个工作表，程序直接读取该工作表，UI 不提供工作表选择。

## 标准文件夹名

文件夹创建与文件夹重命名的目标名称使用以下固定格式：

```text
{序号固定三位左侧补零}——{文件夹名称}
```

分隔符必须是两个中文破折号 `——`，不得替换为连字符、下划线或空格。

示例：

```text
序号：1
文件夹名称：规划管理文件材料
标准文件夹名：001——规划管理文件材料
```

## 占位文件夹流程

共享文件夹可能需要在业务名称整理完成前投入使用。文件夹创建任务允许任务表只填写序号并将文件夹名称留空，此时创建合法的占位文件夹：

```text
001——
002——
003——
```

名称整理完成后，文件夹重命名任务按现有文件夹的三位序号前缀，与任务表中的序号建立唯一对应关系，再将占位文件夹补全为标准文件夹名：

```text
001——  ->  001——规划管理文件材料
```

待处理文件夹必须是本项目创建并具有三位序号前缀的文件夹。若任务目录中缺少对应序号或同一序号匹配到多个文件夹，验证不得通过，也不得开始实际重命名。

文件夹重命名任务遇到空的 `文件夹名称` 时，目标名称仍为对应占位文件夹名，例如 `001——`。该行记录为无变更项，保留原文件夹，不调用文件系统重命名操作；无变更项不属于失败或遗漏。

## 图片重命名任务

- 图片任务表是包含多个工作表和多列的 `.xlsx` 文件，不使用文件夹任务的两列模板。
- 已知存在的列包括：
  - `序号`
  - `文件题名`
  - `页次`
- `序号` 列不参与图片重命名。
- 待处理图片的初始文件名使用三位页码，例如：

```text
001.jpg
002.jpg
003.jpg
```

业务保证图片页码保持三位，不会出现需要四位表示的页码；程序不增加上限校验。

- 图片目标名称由原三位图片页码直接拼接对应文件名称，中间不添加分隔符，例如：

```text
001项目建议批复文件及项目建议书.jpg
```

- `页次` 存在两种已知形式：
  - 单独页码，例如 `001`、`005`；
  - 包含首尾页的范围，例如 `010-017`。

页次区间按以下规则推导：

1. 单独页次表示当前行文件的起始页。
2. 当前行的结束页等于下一行起始页减一。
3. 最后一行必须使用 `起始页-结束页` 格式明确结束页。
4. 页次区间的起始页和结束页均包含在处理范围内。

示例：

| 任务表页次 | 文件名称 | 对应图片范围 |
|---|---|---|
| `001` | 文件A | `001.jpg` 至 `004.jpg` |
| `005` | 文件B | `005.jpg` 至 `009.jpg` |
| `010-017` | 文件C | `010.jpg` 至 `017.jpg` |

对应目标名称包括：

```text
001文件A.jpg
002文件A.jpg
003文件A.jpg
004文件A.jpg
005文件B.jpg
...
017文件C.jpg
```

### 工作表与文件夹绑定

图片重命名任务必须由用户分别选择：

1. 一个 `.xlsx` 图片任务表；
2. 该图片任务表中的一个工作表；
3. 一个由本项目文件夹功能生成或维护的任务目录。

不同工作表对应不同文件夹。工作表名称固定使用不补零数字，例如 `1`、`2`、`3`；任务目录名称必须以三位序号开头，例如 `001——`、`002——规划管理文件材料`。

执行前必须把工作表名称解析为整数，并与任务目录名称前三位序号的整数值比较：

```text
工作表 1 + 文件夹 001——  -> 匹配，允许继续验证
工作表 2 + 文件夹 001——  -> 不匹配，操作错误
```

工作表与文件夹不匹配时，不得生成可执行的重命名计划，也不得修改任何图片。

### 图片任务选择流程

图片重命名任务的输入控件固定按以下顺序排列：

1. 选择 Excel；
2. 选择文件夹；
3. 选择工作表。

选择 Excel 后加载其工作表列表。同一个 Excel 可以在连续处理多个文件夹时保持选中，无需每次重新选择。

选择文件夹后，程序读取文件夹名称前三位序号，去除前导零后得到工作表编号，并自动选中同名工作表：

```text
文件夹 001——  -> 自动选择工作表 1
文件夹 012——某文件夹  -> 自动选择工作表 12
```

用户可以手动修改工作表选择，但手动选择不绕过工作表文件夹绑定校验。若用户为 `001——` 选择工作表 `2`，点击执行时必须提示绑定错误且不修改图片。

若 Excel 中不存在自动匹配的工作表，应保持工作表未选中并明确提示未找到对应工作表。

### 图片扫描范围

图片重命名只处理所选任务目录直接包含的 JPG 文件，不递归扫描或修改任何子文件夹。业务上预期任务目录内不存在子文件夹；即使实际发现子文件夹，也必须忽略其中内容。

### 重复执行

图片重命名任务任何时候都允许重新执行。每次执行必须重新读取当前工作表和当前任务目录，不依赖上一次执行的图片数量、页次区间、旧名称或日志：

- 图片数量可以增加或减少；
- 工作表中的页次区间可以变化；
- 图片文件名前三位页码可以变化；
- 已重命名图片仍使用当前文件名前三位页码匹配；
- 当前题名后缀不参与匹配，目标名称按当前工作表重新生成；
- 当前名称已等于目标名称时记录为无变更项。

例如第一次区间包含 3 页时修改 3 张图片，第二次区间变为 4 页时，重新按当前状态计算并修改 4 张图片。

### 图片完整性前提

业务保证工作表页次范围对应的 JPG 始终完整，不会发生期望页码缺少图片的情况。首版不提供补页、跳过缺页或缺页后的部分执行功能。

该业务前提不取消通用文件系统错误处理；文件被占用、权限不足或重命名失败时仍必须停止后续修改并报告错误。

### 规范输入前提

业务保证 `文件题名`、任务表字段和待处理文件满足约定格式及 Windows 文件名规则。非法字符、错误页次、错误人工录入等上游失误不在首版处理范围内：

- 不自动替换或清洗文件题名；
- 不尝试推测或修复错误数据；
- 不建设复杂的数据恢复流程。

工作表编号与任务目录前三位序号的一致性校验属于已明确要求，仍必须执行。

## 执行交互

- 用户选择当前任务所需输入后，点击执行按钮直接开始操作。
- 必要校验通过后不得再弹出确认框。
- 不提供复杂的逐项预览表。
- 不要求用户针对每个工作表进行二次确认。
- 工作表与文件夹绑定不匹配时，执行按钮触发错误提示，不修改文件。
- 正式版执行成功后不弹确认框，在当前标签页底部显示完成数量。
- 正式版执行失败时在当前标签页显示失败对象和原因。

## 失败处理

文件系统操作因文件占用、权限或其他运行时原因失败时：

1. 立即停止尚未开始的后续操作；
2. 在 UI 中显示失败文件或文件夹及系统错误原因；
3. 保留此前已完成的操作；
4. 不复制备份；
5. 不自动回滚；
6. 用户排除问题后重新点击执行。

任务设计必须支持安全重复执行，使再次执行时已达到目标名称的项目成为无变更项。

## 页面组织

应用使用单一主窗口，并提供三个相互独立的标签页：

1. 创建文件夹；
2. 重命名文件夹；
3. 重命名图片。

每个标签页拥有并保存自己的输入选择和操作状态。标签页之间不得共享或覆盖任务目录；图片标签页可在连续操作中保持已选择的 Excel。

UI 使用 `Tkinter/ttk` 实现，以清晰、可操作和稳定为验收重点，不要求复杂视觉效果、动画或现代化主题。

## 便携交付与 Win7 验证

- 交付物是一个完整便携目录，目录内包含 EXE、Python 运行时和全部运行依赖。
- 客户机不得安装 Python、依赖库、Microsoft Excel 或 WPS 组件。
- 用户必须复制整个交付目录，不得只复制 EXE。
- 复制到 64 位 Windows 7 旗舰版 SP1 后，直接双击目录中的 EXE 启动。
- 开发侧负责验证代码、依赖收集、目录完整性及当前构建环境运行。
- 用户负责在另一台真实 64 位 Windows 7 SP1 电脑完成最终兼容性测试。
- 未取得真实 Win7 测试结果前，只能声明目标兼容，不得声明 Win7 已验证通过。

### 测试版与正式版

测试版和正式版必须使用同一份业务代码和依赖锁定，只允许启动配置不同：

- 测试版使用完整便携目录，启动时同时显示 CMD 控制台，用于输出运行步骤、日志和异常信息。
- 正式交付版使用完整便携目录，启动时不得出现 CMD 控制台，只显示 Tkinter UI。
- 正式版不得因为隐藏控制台而吞掉错误；运行结果和失败原因必须能够通过 UI 获知。

### 打包工具

- 使用 Python 3.8 虚拟环境中的 PyInstaller 4.10。
- 使用 `onedir` 模式，不使用 `onefile`。
- 开发虚拟环境只用于开发、测试和打包，不复制到交付目录。
- 交付目录由 PyInstaller 收集 Python 运行时、Tk/Tcl、`openpyxl` 及间接依赖。
- 客户机离线运行，不使用网络、pip、系统 Python 或客户机办公软件。
- 交付目录必须自包含全部运行依赖，不得要求客户机安装 .NET Framework、Java、Visual C++ 运行库安装包或其他外部环境。
- 应用运行期间不得联网下载或更新组件。
